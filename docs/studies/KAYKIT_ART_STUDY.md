# KayKit art study

Topaz's first art audition uses free KayKit packs by Kay Lousberg in the existing Bootstrap scene. These models are a visual baseline for review, not a final art commitment. The world remains hand-authored and the combat/gathering rules remain Topaz code.

## Imported library

The owner supplied 11 free KayKit download folders on 2026-09-23: Adventurers 2.0, Block Bits 1.0, Character Animations 1.1, Dungeon 1.1, Fantasy Weapons Bits 1.0, Forest Nature 1.0, Furniture Bits 1.0, Halloween Bits 1.0, RPG Tools Bits 1.0, Resource Bits 1.0, and Skeletons 1.1. Each folder included Kay Lousberg's CC0 1.0 license. The Unity project contains the Unity-oriented FBX export of every unique model, character and animation FBX files, required texture atlases, and the exact license text under `Assets/ThirdParty/KayKit/<pack>/`. Each pack's `SOURCE.md` records its free download folder, acquisition date, imported file counts, and SHA-256 tree digest of the original extracted download. Duplicate OBJ, glTF, generic FBX exports, sample images, and web shortcuts were omitted. The original extracted folders are retained in the ignored local archive `LocalSourceArchives/KayKit/`.

KayKit's [official asset catalog](https://kaylousberg.com/game-assets) links the pack pages. The [Forest](https://kaylousberg.itch.io/kaykit-forest), [Resource Bits](https://kaylousberg.itch.io/resource-bits), and [RPG Tools](https://kaylousberg.itch.io/rpg-tools-bits) pages explicitly describe free CC0 tiers. All imported files retain the exact `LICENSE.txt` supplied with their downloaded pack. See [the third-party asset register](../THIRD_PARTY_ASSETS.md) and the per-pack source notes for provenance.

Git LFS tracks the FBX source binaries. Unity imports active models as assets; only referenced models enter a player build. The first scene uses Rogue, Skeleton Minion, forest trees and rocks, a Wood log pickup, an axe and sword, and dungeon furniture. On 2026-09-24, the owner moved 69 rejected FBX models to `ArtArchive/KayKit/` outside Unity's `Assets/` folder; unmarked models remain available for later authored scenes. URP materials reference the packs' own atlas textures. See [the asset review workflow](../ASSET_REVIEW.md).

The home and expedition clearing now reuse the already imported `Dungeon/Models/floor_dirt_large.fbx` as 4 m floor tiles and the `Forest/Models/Grass_1_A_Color1.fbx` and `Grass_2_A_Color1.fbx` clumps as sparse decoration. The existing flat ground colliders and NavMesh remain authoritative; these visual meshes have no collision. `Topaz/Apply KayKit Ground Art` rebuilds this deterministic scene art. No new third-party files or license terms were introduced. The former ground-wear decals were removed.

## Review in the Mac build

At Topaz's fixed orthographic camera, check the silhouettes, scale, palette, ground contrast, weapon readability, and whether attack tells remain visible over the forest forms. The art study keeps the existing movement and combat graybox mechanics. Character animation, lighting polish, and a wider environment layout need separate review before we treat KayKit as the production style.

The tree now drops a visible, saved Wood bundle on its final chop. Walking close to a drop collects as much as the backpack can hold; any remainder stays in the world. Every successful tree chop earns Logging XP, and every sword hit that actually damages the enemy earns Swords XP. Neither uses a per-target award cap. Saves use version 3; earlier versions migrate. Disk writes run on a background task and rapid changes coalesce, with a flush when the player pauses or quits.

## Character animation audition

The Rogue and Skeleton use Unity's built-in Generic Avatar and Animator Controller. The imported KayKit animation files share the exact 24 bone paths checked against the Rogue, so this pass uses their native Generic rig instead of Humanoid retargeting. The Rogue uses a two-dimensional aim-relative blend of idle, `Running_A`, left/right running strafes, and `Walking_Backwards`. The backward clip's playback rate matches the forward run's cycle cadence; review its foot placement at gameplay speed. The Rogue also plays four direction-specific dodges, a short hit reaction, sword slice, and axe chop. The Skeleton keeps a one-dimensional idle/walk blend and plays an unarmed strike, hit, and death. Selected clips are copied into `Assets/Topaz/Characters/Animation/Clips/` so locomotion loops can be configured without editing KayKit's source animation files. Unity creates the character Avatars from each FBX and uses `Rig_Medium/root` as the motion node.

The small `CharacterAnimationDriver` only selects poses and adjusts playback speed to the existing gameplay durations. The CharacterController, NavMeshAgent, combat phases, hit checks, dodge invulnerability, and save data still own the actual outcomes. Root motion is off. Actual planar movement is projected onto the aim direction for the Rogue's directional blend; this also stops the run pose when collision blocks movement. The equipped sword or axe remains visible in the Rogue's right hand while idle, moving, dodging, and attacking; the older pivot meshes are hidden, while the ground arc remains the range/timing cue. The dodge movement and invulnerability still last 0.18 seconds, but its pose finishes over 0.36 seconds so it reads at gameplay scale. A new attack or hit reaction can replace that visual finish. Hit clips play briefly when a character is not in a committed attack; hits during an attack still show the existing color flash. The Skeleton's punch reaches full hand extension about halfway through the source clip, so its windup and recovery playback rates place that frame at the end of the 0.65-second red tell, when gameplay resolves the strike. The Skeleton stays visible for its death pose while its collision and navigation are disabled, then respawns under the existing practice rule.

Run `Topaz/Apply Character Animation Study` to refresh this scene. `Topaz/Apply KayKit Art Study` also reapplies the animation setup after rebuilding its models. No extra Unity package was needed: Timeline is for authored sequences, and Animation Rigging would be useful later only if hand placement or aiming needs procedural correction. Review strafe and backpedal foot placement, the four dodge silhouettes, and whether the punch contact reads with the red tell at gameplay size.
